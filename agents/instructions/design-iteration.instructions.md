# Adventure 分析文迭代规则

本规则只适用于 WorldGeo-AdventureAddon 仓库 `design/analysis/` 下的分析文档。

`design/analysis/` 用于存放带时间戳的分析、批判、复盘与方向判断文件。文件名统一写成 `YYYY-MM-DD-HHMM-主题.md`。

当任务内容要求系统性评估、批判现有设计、比较方向或写阶段判断时，采用内部五轮迭代流程。五轮属于生成过程，不自动进入正式正文。

正式正文与附录中的迭代记录，只写 Adventure 当前设计本身。正文以 `design/README.md` 与 `00-overview.md` 到 `08-regional-templates.md` 为主要对象；`direction_proposals.md` 属历史归档，只在旧思路已经回流现有正文时引用。

正文判断至少覆盖四类问题：

1. 哪些部分合理，且值得保留。
2. 哪些思路已经老套，只是看起来完整。
3. 哪些假设对当前 Minecraft 玩家圈子不切实际。
4. 哪些部分实现成本或维护成本过高。

合理和不合理都要给出依据，不写情绪化裁决，不把“我不喜欢”写成“设计错误”。

1. 先生成设计初稿，形成主要框架和核心命题。
2. 对初稿做系统性批判，找出不够具体的思路、缺乏数据支撑的论断、遗漏的关键角度，并基于批判结果修订设计。
3. 在上一步修订后继续批判，要求敢于大胆猜想，也敢于在辨别之后彻底抛弃不成立的旧有思路；循环至第五轮。
4. 最终分析只保留最终判断、依据与机制，不把五轮过程写回正式正文，不在正文或附录中强制保留完整迭代日志。
5. 用户明确要求保留推演过程时，另写同时间戳的 `-worklog.md` 归档到 `design/analysis/`；流程图、轮次记录和被抛弃的判断只放在该工作记录中，不回灌正式分析文。
6. 正式分析文不得用“上一篇文章”“本文只看”“这一轮”“最终收束为”“价值在于”“边界在于”这类过程话语组织正文。
7. 当分析文继续前文脉络、主体转向分期、版本口径或落实方案时，正文开头仍要用 1 到 2 段把四类判断补回当前文件。单篇正式分析文必须能独立成立，不能把关键依据留给前一篇。
